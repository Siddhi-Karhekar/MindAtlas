# Deploying Mind Atlas

**What is live:** two free **Render** services that auto-deploy from `main`,
and a free **MongoDB Atlas** database. `render.yaml` is the written record of
both services' settings.

| Piece | Where | URL |
| --- | --- | --- |
| Client (React, static files) | Render **Static Site** `mindatlas`, root `client/` | https://mindatlas.onrender.com |
| API (Express) | Render **Web Service** `mindatlas-api`, root `server/` | https://mindatlas-api.onrender.com |
| Database | MongoDB Atlas **M0**, AWS Mumbai (`ap-south-1`), database `mindatlas` | — |

The browser loads the site from `mindatlas.onrender.com` and calls the API on
`mindatlas-api.onrender.com`, so the API must allow that origin
(`CORS_ORIGIN`). Putting both behind one address is a pending step - see
"Still to do" below.

Why this setup:

- **Render** builds straight from the GitHub repo and redeploys on every push to `main`.
  It gives free HTTPS and a public URL, and it runs a normal long-lived Node server.
  That matters here: OCR (tesseract.js), PDF parsing and the in-memory rate
  limiter all need a real server. Serverless hosts like Vercel or Netlify
  functions are not a good fit for them.
- **MongoDB Atlas** is required in production. Without `MONGODB_URI` the app uses
  its local file database (`server/data/mindatlas-db.json`). That is fine on
  your own laptop, but Render's disk is temporary, so every account and note
  would be wiped on each redeploy. On Render the server now refuses to start
  without it.

Total cost: ₹0.

## 1. Database: MongoDB Atlas (~10 min)

1. https://cloud.mongodb.com → **Create** → **M0 Free**, AWS **Mumbai (ap-south-1)**.
   Untick "Preload sample dataset" (it eats the 512 MB quota).
2. **Database Access → Add New Database User**: password auth, an autogenerated
   password (letters and digits only, so it needs no URL-escaping). Under
   **Specific Privileges** give it **`readWrite` @ `mindatlas`** and no
   built-in role, so a leaked connection string can only touch this app's data.
3. **Network Access → Add IP Address → Allow access from anywhere**
   (`0.0.0.0/0`). Render's free tier has no fixed outgoing IP.
4. **Clusters → Connect → Drivers** → copy the string and put the password in
   place of `<db_password>`, **removing the `<` `>` too**:
   `mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/?appName=Cluster0`.
   The app always uses the database `mindatlas`; no need to add a name.

## 2. API: Render Web Service (~5 min + build)

**New + → Web Service →** the `Siddhi-Karhekar/MindAtlas` repo.

| Setting | Value |
| --- | --- |
| Name | `mindatlas-api` |
| Region | Singapore (closest to the Mumbai database) |
| Branch / Root Directory | `main` / `server` |
| Build / Start Command | `npm ci` / `npm start` (the optional MiniLM model is not installed on the free plan - see `SEMANTIC_MODEL` below) |
| Health Check Path | `/api/health` |
| Instance type | Free |

Environment - **spell the keys exactly**:

| Key | Value |
| --- | --- |
| `NODE_ENV` | `production` |
| `NODE_VERSION` | `22` |
| `TRUST_PROXY` | `1` (so rate limits see each visitor's address, not Render's proxy) |
| `SEMANTIC_MODEL` | `off` on the free plan: with the model loaded, a big phone photo peaked at ~576 MB during OCR (limit 512 MB) and Render killed the API. Notes get links by meaning from a relink run on a machine with the model: `npm run relink -- --live --all --yes` after a fresh `npm run db:backup` |
| `MONGODB_URI` | the Atlas string from step 1 |
| `JWT_SECRET` | 32+ random characters: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"` |
| `CORS_ORIGIN` | `https://mindatlas.onrender.com` (after step 3; exact origin, no trailing `/`) |
| `GROQ_API_KEY` | optional, free at https://console.groq.com/keys - AI-written questions and marking; blank = rule-based fallback |

| `LLM_VISION_MODEL` | optional, default `qwen/qwen3.8-27b` (Groq's image model, used to read photos of handwritten answers); `off` reads them with OCR instead and flags them for review |
| `ANSWER_IMAGE_MAX_MB`, `ANSWER_IMAGES_MAX_PER_STUDENT` | optional, defaults `5` and `300`: size of one answer photo (the browser shrinks photos to about 0.2-0.6 MB first) and how many a student may keep |
| `UPLOAD_MAX_MB` | optional, default `10` (capped at 25 because files are read in memory on a 512 MB instance). The upload screen shows this value. PDFs are also limited to 400 pages and photos to 50 megapixels (`server/src/config.js`) |

More optional ones are under "Settings for running it for real" and "Email".

When it is live the **Logs** show `[db] connected to MongoDB`, and
`/api/health` returns `"ok":true` with `"db":{"kind":"mongodb","persistent":true}`.

## 3. Client: Render Static Site (~3 min)

**New + → Static Site →** the same repo.

| Setting | Value |
| --- | --- |
| Name | `mindatlas` |
| Branch / Root Directory | `main` / `client` |
| Build Command | `npm ci && npm run build` |
| Publish Directory | `dist` |
| Environment | `VITE_API_BASE=https://mindatlas-api.onrender.com/api` |

`VITE_API_BASE` is baked in when the site is built: if it changes, **Manual
Deploy → Deploy latest commit**.

- **Redirects/Rewrites → Add Rule**: source `/*`, destination `/index.html`,
  action **Rewrite**. Without it, refreshing any page except the home page is
  "Not Found".
- **Headers** (path `/*` each): `X-Frame-Options: DENY`,
  `Referrer-Policy: no-referrer`,
  `Permissions-Policy: camera=(), microphone=(), geolocation=()`. Render adds
  `Strict-Transport-Security` and `X-Content-Type-Options` itself.

Then set `CORS_ORIGIN` on the API (step 2), sign up on the site, and check that
Atlas → Browse Collections shows the `mindatlas` database.

## Things to know

- **Cold starts (free plan):** the service sleeps after 15 minutes with no traffic.
  The next visitor then waits about 30–60 seconds while it wakes up.
  Before a demo or viva, open the site a minute early. You can also point a free
  uptime pinger such as https://uptimerobot.com at `/api/health` every 10
  minutes, or upgrade to Render's Starter plan (~$7/month) to stop it sleeping.
- **OCR:** the first image upload after each wake-up is slower, because
  tesseract downloads its English language model first.
- **Memory:** the free plan has 512 MB of RAM. That covers normal use, but very
  large PDFs or many simultaneous OCR uploads could run out.
- **Custom domain:** in Render go to Settings → Custom Domains. HTTPS is set up automatically.
- **Groq limits:** the Groq free tier is rate-limited. If it is exceeded, the app
  falls back to rule-based questions and grading on its own.

## Rolling back a bad deploy (2 minutes)

A deploy that breaks the site is undone on Render first, and fixed in Git
afterwards, so students are not left waiting while the fix is written.

1. **Put the last good version back:** Render dashboard → the service →
   **Deploys** → the last deploy that worked → **Rollback** → **Rollback to
   this deploy**. Render redeploys that build (with that deploy's environment
   variables); the site is back within a couple of minutes. A rollback from the
   dashboard turns off auto-deploy, so the next push does not bring the problem
   straight back. ([Render: rollbacks](https://render.com/docs/rollbacks))
2. **Undo the change in Git:** on your computer,
   `git revert <the bad commit>` then `git push`, or revert the pull request on
   GitHub (its page has a **Revert** button). Then turn auto-deploy back on in
   Render (Settings → Build & Deploy).
3. **The database is not rolled back.** Code changes in this project only add
   fields, so an older version reads newer data. If a change ever renames or
   removes a field, restore the data from a backup as well (see "Backups").

Check after either step: `/api/health` answers `{"ok":true,...}`, you can sign
in, and a test starts.

## Settings for running it for real

All optional; set them on `mindatlas-api` (Environment) and redeploy.

| Variable | What it does |
| --- | --- |
| `SUPPORT_EMAIL` | The address students write to for help or with a complaint (shown on the sign-in and Settings pages). Name one before real students use the app. |
| `ADMIN_USER_IDS` | Account ids (comma-separated) that may open `/admin`: reported questions, suspending an account, sign-up numbers. An account's id is on its Settings page. |
| `LLM_API_URL`, `LLM_MODEL` | Use another AI provider or model (any OpenAI-compatible chat API). The key stays in `GROQ_API_KEY`. |
| `NOTES_MAX_PER_STUDENT`, `NOTES_MAX_CHARS_PER_STUDENT` | Each student's storage ceiling (default 2,000 notes, 30 million characters). |

## Email (optional)

With an email account configured the app asks new users to confirm their
address and offers "Forgot password?". Without one, neither is offered and
everything else works. Set on the API service:

| Variable | Example |
| --- | --- |
| `SMTP_HOST` | `smtp.gmail.com` (use an "app password") or `smtp-relay.brevo.com` |
| `SMTP_PORT` | `465` for Gmail, `587` for Brevo |
| `SMTP_USER`, `SMTP_PASS` | the mail account's sign-in |
| `MAIL_FROM` | `Mind Atlas <you@example.com>` |
| `APP_URL` | the address students open, e.g. `https://mindatlas.onrender.com` |

`/api/health` shows `"email":{"enabled":true}` once it is on. The security
settings and the remaining deploy steps are in
[`docs/SECURITY.md`](docs/SECURITY.md).

## Backups (Atlas M0 has none)

Take one before anything that rewrites data on the live site (a migration,
the graph relink tool), and before demos.

1. Once: add the live string to `server/.env` as **`ATLAS_URI=`** - not
   `MONGODB_URI`, which would point your local dev server at the live data.
2. `cd server && npm run db:backup` writes
   `server/backups/mindatlas-<UTC time>/`: one JSON file per collection and a
   `manifest.json` with the counts. The folder is git-ignored; it holds every
   student's notes and password hashes, so keep it private and never commit or
   share it.
3. To put a backup back: `npm run db:restore -- backups/mindatlas-<time>`
   shows what would change; add `--yes` to do it. Each collection in the
   backup is emptied and refilled. Set `RESTORE_URI=...` to restore somewhere
   other than `ATLAS_URI` (a local test database) - practise there first.

## Relinking the graph (after a keyword or linking change)

Notes keep the keywords and links they were given when they were saved. After
deploying a change to how those are worked out (`server/src/services/tfidf.js`
or `graphEngine.js`), bring the existing notes onto the new rules:

1. `cd server && npm run db:backup` - the relink refuses to write to the live
   database without a backup of it from the last 24 hours.
2. `npm run relink -- --live --all` shows, per student, the links before and
   after. Nothing is written.
3. `npm run relink -- --live --all --yes` applies it. Running it again is safe:
   the second run changes nothing. Links students removed stay removed.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| Deploy fails: `MONGODB_URI is not set, but MONDODB_URI is` | The key is misspelled on `mindatlas-api` (this happened: every account vanished on each restart until it was fixed) |
| Deploy fails: `MONGODB_URI is not set on Render` | The variable is missing on `mindatlas-api` |
| Logs: `bad auth : authentication failed` | Wrong password in the string, or the `<` `>` placeholder brackets are still there |
| Logs: `MongoServerSelectionError` | Atlas Network Access lacks `0.0.0.0/0` |
| Logs: `not authorized on mindatlas` | The Atlas user lacks `readWrite` on the `mindatlas` database |
| Site says "Failed to fetch" | `CORS_ORIGIN` is not exactly `https://mindatlas.onrender.com`, or the API is still waking up |
| Refreshing a page gives "Not Found" | The static site's `/*` → `/index.html` rewrite rule is missing |
| Events show "Out of memory", or the API keeps restarting | The MiniLM model (~130 MB) plus big OCR/PDF uploads exceeded 512 MB: set `SEMANTIC_MODEL=off` in Environment. `/api/health` then shows `"semantic":{"active":false}` and cross-subject links use TF-IDF |
| AI questions are off | `GROQ_API_KEY` is blank - `/api/auth/config` shows `"ai":{"enabled":false}` |

## Rebuilding from the Blueprint

`render.yaml` recreates both services: **New + → Blueprint → this repo**. Use
it for a fresh workspace, or after deleting the old services; next to the
existing ones it would clash on their names. It asks for the values marked
`sync: false` and generates a new `JWT_SECRET` (everyone is signed out once).
If Render gives the API a different URL, update `VITE_API_BASE` and
`CORS_ORIGIN` to match.

## Other ways to run it

- **One container** (`Dockerfile` in the repo root): builds the client and
  serves it from the API on one URL, so no CORS is needed. Runs on Railway,
  Fly.io, Koyeb, Cloud Run or any VPS with `NODE_ENV=production`,
  `JWT_SECRET` (32+ characters), `MONGODB_URI`, `TRUST_PROXY=1`, and
  optionally `GROQ_API_KEY`. The root `package.json` (`npm run build` /
  `npm start`) does the same without Docker.
- **Locally, like production**: `docker compose up --build`, then
  http://localhost:4000 (that image plus its own MongoDB, never the live one).
